# PostgreSQL setup adversarial audit — 19 October 2026

The owner requested a full audit of the preceding local Docker/PostgreSQL setup and authorised fixes/refactoring. This review checks both the successful path and failure/isolation behavior; the previous passing application suites did not establish those script boundaries. This supplements the [original execution record](LOCAL_POSTGRES_2026_10_19.md). No open product policy, hosted provider or production release is decided here.

## Findings and corrections

| Finding | Correction and evidence |
| --- | --- |
| **Session isolation was incomplete.** Both apps used `127.0.0.1` and `qf_session` with path `/`. Ports do not scope browser cookies, so signing into one could replace the other's session cookie. | The PostgreSQL preview's canonical origin is now `http://localhost:3001`; the existing app remains `http://127.0.0.1:3000`. Live readiness, account picker, Admin login and authenticated context passed at the new origin. Use the documented hostnames; the IPv4 bind stays loopback-only. |
| **Docker/Compose commands inherited the caller's target.** A different context, `DOCKER_HOST`, Compose file or project name could redirect commands or produce a different volume. | Every command pins `desktop-linux`, verifies the local Linux named pipe, and pins the Compose file, project `qfwebapp`, directory and `.env.example`. Actual setup/status succeeded with deliberately invalid foreign Docker/Compose environment values. A remote endpoint under the expected context name is refused. Existing volume/service identity is retained. |
| **Tests inherited development defaults.** Only `TEST_DATABASE_URL` selected test schemas; `APP_ENV`, `DATABASE_URL` and the helper flag still defaulted to development. A test using implicit config could reach development. | The test action now defaults all of these to test, with `memory://` for embedded scratch paths and account helper disabled. Both the test harness and real suite exercise this action. |
| **Executable selection was not robust.** Mere presence of Node did not enforce the required major version. The adversarial command test also reproduced PowerShell returning multiple executable paths when a `.cmd` and `.exe` coexist. | Select the first application on PATH explicitly and enforce `v24.*` before container mutation. A Node 20 test verifies no `up` command was issued. |
| **The backup evidence was too narrow.** The earlier restore used the container-side original rather than round-tripping the saved Windows artifact, and checked a few counts. There was no repeatable backup/verification command. | `backup` exports one repeatable-read source snapshot, fingerprints all public-table rows, runs `pg_dump` against that exact snapshot, saves the artifact, copies that saved artifact back and restores into a fresh database. It compares every public table's count and content hash and writes an ignored immutable manifest. Failures retain artifacts and never replace a source database. |
| **Audit-commit failure was untested.** The previous regression tested delay/ordering but did not prove what happens when the independent transaction fails. | A new test forces the event insert to fail: HTTP 500 releases no protected content or SQL/private details and commits no partial event. Retry commits one event; denied access is still recorded. This passes against PostgreSQL and PGlite. |
| **High: audit errors during an existing error response could expose raw database details.** A live invalid-origin request to a malformed Support ID returned PostgreSQL code/message through Fastify's fallback handler. Origin checks run before parameter validation; throwing again in `onSend` can bypass the custom error envelope. | Reject noncanonical UUID resource identifiers before audit queries, preserving the original 403 envelope. Catch audit failures inside `onSend` and return the shared sanitized JSON failure directly, including denied responses; clear attachment/content-length headers when replacing a download. Regressions failed before correction, then verified allowed/denied/download failure, rollback, retry and no private error text on both adapters. Live checks on both apps now return `ORIGIN_INVALID` without SQL details. |
| **CI did not exercise the Windows helper, duplicated branch checks, and had no job timeout.** | A Windows job runs eight isolated command-boundary checks without Docker/dependencies. Branch-based concurrency cancels superseded/duplicate events; jobs have bounded timeouts and a read-only source token. The backend still runs both database suites. |
| **The normal app had not loaded the source fix.** The old PID 35128 remained healthy but still ran the earlier `onResponse` hook. | Verified that its console contained only that app and the shutdown helper, sent graceful SIGINT, and observed clean engine/runtime-lock removal. Copied and verified all **1,475 cold database files** before restarting the same configured database on current source, PID **32212**. Readiness passed; `.env`'s byte checksum is unchanged. No fixtures/reset, runtime-marker deletion, database-path switch or paid provider request occurred. |
| **Seed metadata was stale.** The fixture manifest still identified Chapters 01–02 and described labels/titles inaccurately, despite later warning settings. | Updated its version and scenarios to the actual Chapters 01–18 baseline. The organisation remains unverified; no automatic trade verification or business/financial history was invented. |

## Boundaries and concerns

The PostgreSQL data is a fictional baseline, not a migration of the existing PGlite app. **The intermittent embedded-engine abort remains unexplained**, even if a bounded rerun passes; do not infer a general reliability guarantee from isolated success. Malware scanning remains unavailable; uploads intentionally remain processing without a working scanner. A database-only backup does not preserve local account-helper encryption keys, security mailbox or external evidence; cross-machine/production recovery still requires those and separate recovery exercises. Restores are fresh local check databases retained for inspection; no retention/deletion schedule is inferred. No production identity/private-storage/hosting, load/device/accessibility certification or open product-policy gate is claimed complete. Source control is not a process supervisor; use an owner-managed terminal or the documented development process lifecycle.
