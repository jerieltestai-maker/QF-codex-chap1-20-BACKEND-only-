# ADR 009 — Versioned warning clearance and private decision packs

Accepted for local construction, 18 October 2026. The owner's explicit G12 answers in PRODUCT_MEMORY.md and OPEN_DECISIONS.md supersede the earlier advisory-only proposal.

The four initial warning values are 20% quote revision, 30% selected-price gap, 20% cumulative variation growth and three comparable quotes. Settings require all four values and an initially unchecked prospective-effect acknowledgment. MCST and Admin may edit; Admin must give a reason, as must ticket overrides after bidding starts. Estate changes bind the next explicitly opened quotation round; ticket overrides govern later ticket events. Freeze the applied settings and complete evidence on each immutable grouped warning card. Never recalculate historical cards on notification delivery or settings changes. Ticket setting changes increment the job version so earlier decision screens cannot submit against unseen rules.

Use integer cents and bigint cross multiplication for inclusive percentage thresholds. Rounded percentage strings are presentation only. The quote-revision baseline is the first quote in the same material scope; a new material scope gets a new baseline. Compare selected price against the exact valid selectable set. Variation growth compares the selected baseline against the approved total plus this proposal's delta. Pending proposals are never accumulated as authorised cost. New quotes must be at least SGD 0.01; the NOT VALID database check preserves historical zero records while rejecting new ones. Invoice reductions, settlements and refunds can still reach zero. Legacy missing/zero denominators produce explicit unavailable evidence rather than fabricated arithmetic.

A flagged CM selection routes into the existing exact nomination approval, even below the monetary threshold. MCST may combine selection/approval/explicit warning clearance and a required explanation. Revision flags follow the selected exact quote, not rival bidders. A flagged variation creates an independent work hold: Start, ordinary progress and completion cannot proceed until explicit MCST/Admin clearance. Withdrawal, rejection, other status corrections and generic Support cannot erase that hold. Necessary make-safe documentation stays available. Clearing a warning does not approve the proposed extra work or execute a payment. Distinct review dispositions never imply clearance. Every clearance preserves the exact source version, explanation, named authority and server time.

Both MCST and Admin get a grouped in-app warning notification. Reuse existing nomination/variation response tasks and clocks. Independent warning reviews and holds do not invent new product deadlines. Access logging is committed independently of a refused command, recording only resource, actor, projected audience, allowed/denied outcome and server time. Do not record cookies, grants, filenames, request bodies or allegation text. Denied access creates one outstanding Admin attention item per actor/resource; ordinary authorised viewing is not a misconduct signal. Subject exclusions also filter security tasks and log counts. Detailed logs are Admin-only; an explicitly approved summary is separately stored for MCST.

Dashboards query canonical records and permission-filter tasks before search, counts and paging. MCST inherits CM operational tasks. Informational notices have an explicit flag and cannot become additional queue obligations while awaiting delivery. A future reminder does not make an already actionable approval scheduled. Workspace detail and ticket summaries share the same waiting-actor projection. Work holds remain a separate fact from ordinary work status and financial obligations.

Export requests atomically capture a role-filtered immutable snapshot, exact source version, audience and operation receipt, then enqueue normal durable work. HTML is printable and JSON retains structured evidence; no PDF generator is claimed. Shared worker leases, retries and persistent-failure monitoring apply. Generation reconstructs the requester's current membership and checks access version and concealment; download repeats those checks with an authenticated 15-minute revocable grant. Files are private database bytes, never a public static directory or a bearer-only URL. Export status identifies later versions and financial corrections while preserving the original bytes/checksum.

CM masking covers historical identifiers, nested selection/AI text, actor records, attachments and export metadata. Contractor packs contain only their own quotes and permitted work, without rival submissions or selection rationale. General decision packs exclude confidential conduct material, private negotiation/moderation notes, restricted originals and QuoteFix fees. Evidence references retain their ordinary file authorization. Production analytics exclude explicitly fictional records and never infer clean outcomes from unanswered Feedback or payment lateness from late reporting.

Migrations 017 and 018 preserve existing data. Existing rounds with no saved integrity policy need an explicit ticket override before new quotes, selections or monetary variations; no retrospective parameters are invented. Test fixtures deliberately use broad test-only settings to isolate earlier chapter suites, while integrity tests explicitly exercise the approved defaults. Development fixture defaults remain the approved 20/30/20/3 values. Server PostgreSQL, managed identity/storage, operational scale, retention/deletion and production release remain Chapter 19 or existing open gates.
