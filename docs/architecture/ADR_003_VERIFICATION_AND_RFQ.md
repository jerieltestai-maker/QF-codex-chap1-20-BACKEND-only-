# ADR 003 — Contractor verification and reviewed RFQ publication

13 October 2026. Local construction of Chapters 05–06. Follows ADR 001/002 and the owner's explicit G06/G07 decisions.

## Backend contracts

Keep the existing TypeScript/Fastify/PostgreSQL modular application. Reuse the transaction, current-access check, record version, operation receipt, append-only audit, private upload, durable outbox and task primitives. No new framework, paid provider or production environment is introduced. Consequential commands acquire the same bounded transaction lock as membership and worker mutations; this is a correctness choice for local construction, not a throughput claim.

Trade rules begin unconfigured. Only Admin explicitly configures each category and records a reason; an empty prerequisite list is a deliberate decision, never a default certification policy. Company/person credential types have immutable holder-kind/category definitions. Eligibility requires an approved organisation/profile, every requested trade approved, configured required credentials currently valid, and no applicable restriction. The all-trade check covers combined RFQs; priorities have no role in eligibility. Subcontractors cannot supply missing accountable-company eligibility until the owner defines that policy.

Credential evidence uses organisation-scoped private uploads and the existing scanner/checksum/type pipeline. CM/MCST and rivals cannot download it. Submitted evidence/reference, holder and expiry are immutable versions; each decision identifies its target version, Admin, reason, timestamp and private findings. Verified renewal promotes an approved submission pointer. A pending renewal leaves the previously approved evidence usable until its actual expiry; it cannot extend validity by merely uploading. Approving expired evidence is refused. A renewal approval and old expiry processing cannot race past their transaction lock.

Date-only credentials remain valid through their stated Singapore date and expire at following midnight. Month-before reminders clamp to the previous month's last day, use Singapore midnight for date-only input, and preserve the Singapore time for an explicit timestamp. Recording approved evidence inside the window issues attention on the next worker tick. Current approved submission markers deduplicate renewal/expiry effects. Required lapse creates affected-eligibility/active-work Admin review; optional lapse changes the badge only. Existing work is never automatically cancelled. Fee/manual/credential holds stay separate; the generic Admin lift endpoint cannot clear a financial hold.

## RFQ versions and privacy

Private original observations, original file objects, editable intake, local assistance output and immutable published RFQ snapshots remain separate. Saving intake changes the workspace version but cannot alter an existing publication. Publication validates current estate authority, exact version, facts/privacy confirmation, configured routing and ready permitted evidence. It atomically creates revision, scope version, quotation round, rule snapshot, audit, urgent task and outbox work. RFQs do not expire.

Only explicitly reviewed sanitized PNG derivatives can currently be published; originals and PDFs remain private. Exact estate names and email contacts are additionally rejected in public text. Those checks supplement required human review of text and visible image identifiers; they do not claim complete automatic redaction. Contractors receive explicit projections without estate ID/name, author/contact, original observations, group identities or private evidence. File reads independently repeat current eligibility and published-evidence checks. Estate readers receive a job-scoped public badge projection; a masked CM gets a stable alias with no private contacts, holders, references or authenticity notes. The estate masking column is ready for its later MCST settings controller; no MCST integrity defaults are invented here.

Author-declared spelling/formatting revisions retain the scope version. Material scope/quantity/terms/safety/access/uncertain revisions increment it and emit reconfirmation intent. The server refuses minor classification when structured scope fields or numeric quantities change. Semantic spelling versus meaning remains the named human author's judgment, with reason and before/after snapshots retained. AI never chooses the classification. Revisions preserve the original round and sourcing timestamp. The Chapter 07 quote services must compare their confirmed scope version with the current published one at submission/selection/coverage; an emitted event alone is not the selection guard.

Separate-repair creation preserves the original as a source and creates linked independent private tickets atomically. Source reports cannot also be published as duplicate RFQs; each child needs its own intake/review/publication. Combined jobs retain one whole-bundle scope.

## Local assistance and follow-ups

`local-extractive-v1` is deliberately a local fallback, not a paid generative AI connection. A durable request preserves original input/version, presents structured observed-fact/location sections and review cautions, and never invents quantities, diagnoses or work methods. The worker cannot replace a newer edit. Human acceptance edits the draft only; privacy review/publication are separate. A future generative adapter needs structured-output validation, fact/evidence provenance, stale-result tests and a separately chosen provider.

T12 credential attention and T15/T19 urgency are bound to real feature records. T16 is anchored at the second following calendar date at noon Singapore time. The coverage dependency accepts distinct current selectable organisations for the exact round/scope and repeats live eligibility; the current default is zero because quotes are Chapter 07. Tested coverage fixtures are explicitly simulated, not fabricated operational quotes. Selection/receipt/fee effects are not implemented by generic timers.

Urgent reads do not acknowledge. The dedicated coordination command records actual attempted/arranged/unresolved outcome, summary, optional known ETA, next action and future follow-up, and supersedes urgent repeats with T11. Attendance arrangement never authorizes or starts work. Informational contractor bells resolve their delivery task after issuance; optional bidding is not treated as an unanswered obligation. Failure retries retain the existing ADR 002 policy.

## Remaining delivery boundaries

Video capture/sanitized video publication is not implemented in this local slice; uploads currently support the existing PNG/JPEG/PDF formats and 10 MiB limit. No FFmpeg/video processor is installed or presumed. External generative AI, regulated prerequisite contents, production identity/scanning/storage, server PostgreSQL execution and deployment remain explicit follow-up/release work. Quote submission/reconfirmation, selected/authorised-work effects, cancellation stopping, rejected-selection new rounds, selection-clock pause/resume, risk settings and full support execution belong to their owning later chapters. No numerical reputation score is fabricated.
